# Security Analyst Agent — 日本語プロンプト例集

> **対象**: Microsoft Defender ポータル / Security Copilot の **Security Analyst Agent**
>
> **データソース**: Defender XDR / Sentinel Log Analytics / Sentinel Data Lake
>
> **参考**: [公式ドキュメント](https://learn.microsoft.com/ja-jp/copilot/security/security-analyst-agent)

---

## 1. 異常検出 (Anomaly Detection)

### サインイン異常

```
過去30日間のサインインログを分析し、通常と異なるサインインパターン（深夜の認証、普段使わない国からのアクセス、短期間での大量の失敗）を検出してください。リスクの高い順にランク付けしてください。
```

### 不審なプロセス実行

```
過去14日間のエンドポイントテレメトリから、通常のベースラインと比較して異常なプロセス実行パターンを検出してください。特に LOLBIN（Living off the Land バイナリ）の利用や、初めて観測されたプロセスに注目して分析してください。
```

### メールボックス操作の異常

```
過去7日間で、通常と異なるメールボックス操作（大量の転送ルール作成、外部ドメインへの自動転送設定、一括メール削除）を行ったユーザーを特定してください。ビジネスメール侵害（BEC）の兆候がないか優先度付きで報告してください。
```

---

## 2. クラスタリング分析

### アラートのクラスタリング

```
過去30日間のセキュリティアラートをクラスタリングし、関連するアラートをグループ化してください。各クラスターの共通パターン（攻撃手法、対象リソース、時間帯）を特定し、最も対処が急がれるクラスターを明示してください。
```

### 類似インシデントの分析

```
過去90日間のインシデントデータを分析し、類似の攻撃パターンを持つインシデントをクラスタリングしてください。繰り返し発生している攻撃キャンペーンがないか特定し、MITRE ATT&CK フレームワークにマッピングして報告してください。
```

---

## 3. リスクスコアリングと優先順位付け

### ユーザーリスク評価

```
過去30日間のユーザーアクティビティを分析し、各ユーザーのリスクスコアを算出してください。評価基準として、異常なサインイン回数、アクセスしたリソースの機密度、アラート発生頻度、権限昇格の試行を含めてください。上位10名のリスクユーザーを優先度順に報告してください。
```

### デバイスリスク優先順位付け

```
企業内のデバイスを脆弱性の深刻度、未適用パッチの数、検出されたマルウェアアラート、ネットワーク露出度に基づいてリスクスコアリングしてください。修復対応の優先順位を付けたレポートを作成してください。
```

### 脆弱性の影響度分析

```
現在検出されている脆弱性を、CVSS スコア、悪用の実績（Exploit in the Wild）、影響を受けるデバイス数、インターネット露出の有無でランク付けしてください。即座にパッチ適用が必要な上位の脆弱性を特定してください。
```

## 4. トレンド分析・時系列分析

### アラートトレンド

```
過去90日間のセキュリティアラートの発生傾向を時系列で分析してください。アラートの種類別に増減のトレンドを可視化し、特に急増しているカテゴリがあれば原因の仮説を含めて報告してください。
```

### フィッシング攻撃の傾向

```
過去60日間のフィッシング関連アラートのトレンドを分析してください。攻撃件数の推移、標的にされた部門や役職の偏り、使われたフィッシング手法（URL、添付ファイル、QRコード等）の変化を可視化してください。
```

### 認証失敗の時系列パターン

```
過去30日間のサインイン失敗イベントを時系列で分析し、パスワードスプレー攻撃やブルートフォース攻撃を示唆するパターンがないか検出してください。攻撃元IPアドレスの地理的分布もあわせて報告してください。
```

---

## 5. 特権アクセス・権限昇格の分析

### 権限昇格チェーン

```
過去30日間で、権限昇格またはロール変更アクティビティの後に機密データへのアクセスが行われたケースを分析してください。正規の管理操作か不正アクセスかを判別し、リスクの高い操作チェーンを特定してください。
```

### 特権アカウント監査

```
グローバル管理者およびセキュリティ管理者ロールを持つアカウントの過去30日間のアクティビティを分析してください。通常と異なる操作パターン、深夜・休日のアクセス、多要素認証のバイパス試行を検出して報告してください。
```

### 条件付きアクセスポリシーの迂回

```
過去14日間で、条件付きアクセスポリシーが適用されなかった、または迂回されたサインインイベントを分析してください。ポリシーのギャップやカバレッジ不足を特定し、改善の推奨事項を含めて報告してください。
```

## 6. データ流出・情報漏えい兆候の分析

### データ流出の兆候

```
過去14日間で、大量のファイルダウンロード、外部クラウドストレージへのアップロード、USBデバイスへのコピーなど、データ流出の兆候となるアクティビティを検出してください。通常のビジネス利用とのベースライン比較を行い、異常な操作を優先度付きでリストアップしてください。
```

### SharePoint/OneDrive の不審なアクセス

```
過去7日間の SharePoint および OneDrive のアクティビティログを分析し、機密ラベル付きファイルへの異常なアクセスパターンを検出してください。外部共有リンクの作成やゲストユーザーによるアクセスに特に注目してください。
```

---

## 7. ラテラルムーブメント・横展開の分析

### ラテラルムーブメント検出

```
過去14日間のネットワークアクティビティとエンドポイントログを分析し、ラテラルムーブメントの兆候を検出してください。RDP、SMB、WinRM、PsExec などのリモート実行ツールの使用パターンと、異常なホスト間通信を特定してください。
```

### Kerberos チケット異常

```
過去7日間の認証ログからKerberosチケットの異常（Pass-the-Ticket、Golden Ticket、Silver Ticket の兆候）を分析してください。通常のチケットライフサイクルと比較して不審なパターンを検出し、影響を受けるアカウントを報告してください。
```

---

## 8. クラウドセキュリティ分析

### Azure リソースのセキュリティ姿勢

```
Microsoft Defender for Cloud のアラートを分析し、クラウドリソースのセキュリティ姿勢を評価してください。最もリスクの高いサブスクリプション、リソースグループ、リソースタイプを特定し、優先的に対処すべき設定ミスをランク付けしてください。
```

### 不審な Azure AD アプリ登録

```
過去30日間で新規登録された Azure AD アプリケーションを分析してください。過剰なアクセス許可の要求、不審なリダイレクト URI、マルチテナント設定を持つアプリケーションを特定し、リスク評価を行ってください。
```

## 9. 予測・予測モデリング

### インシデント発生予測

```
過去180日間のインシデント発生パターンを分析し、今後30日間のインシデント発生傾向を予測してください。季節的なパターン、曜日・時間帯の傾向を考慮し、セキュリティチームのリソース配分に関する推奨事項を含めてください。
```

### アラート量の予測

```
過去90日間のアラート発生データに基づいて、来月のアラート量を種類別に予測してください。急増が予測されるカテゴリがあれば、事前対策の推奨事項とともに報告してください。
```

---

## 10. 包括的なセキュリティレポート

### 週次セキュリティサマリー

```
過去7日間のセキュリティイベントを包括的に分析し、エグゼクティブ向けの週次セキュリティサマリーレポートを作成してください。以下を含めてください：
- 重要インシデントの概要と対応状況
- アラートの発生傾向と前週との比較
- 最もリスクの高いユーザーとデバイスの上位5件
- 推奨アクション
```

### ゼロトラスト成熟度評価

```
現在のサインインログ、条件付きアクセスの適用状況、デバイスコンプライアンス状態、ネットワークアクセスパターンを分析し、ゼロトラスト成熟度の現状を評価してください。改善が必要な領域を優先度順に特定し、具体的な推奨事項を提供してください。
```

## データソースの指定方法

プロンプトの末尾にデータソースを指定できます。

| データソース | 指定方法（プロンプト末尾に追加） |
|---|---|
| Defender XDR（既定） | `Defender XDR のデータを使用してください。` |
| Sentinel Log Analytics | `Sentinel Log Analytics のデータを使用してください。` |
| Sentinel Data Lake | `Sentinel Data Lake のデータを使用してください。` |

### 例

```
過去30日間のサインインログを分析し、異常なパターンを検出してください。Sentinel Log Analytics のデータを使用してください。
```

## 効果的なプロンプトのコツ

1. **分析の目的を明確にする** — 「異常を見つけて」より「権限昇格後の機密データアクセスを検出して」の方が精度が高い
2. **期間を指定する** — 「過去14日間」「過去90日間」など具体的に
3. **優先順位付けを依頼する** — 「リスクの高い順にランク付け」で対処すべき項目が明確になる
4. **可視化を依頼する** — 「時系列で可視化」「グラフで表示」でトレンドを把握しやすくなる
5. **フォローアップで深掘りする** — 最初の結果を見て「上位3件について詳細を教えて」と追加質問する
6. **MITRE ATT&CK マッピングを依頼する** — 攻撃の文脈を理解しやすくなる
